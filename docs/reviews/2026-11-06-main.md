The main issues are a payment amount that is not capped, and a driver suspension that leaves the driver online.

## Major
### 🟠 Payment resolution can keep more than the agreed price, `packages/api/src/routers/admin/bookings.ts:419`
**Problem**: `resolvePayment` accepts any retained amount from 0 to 10,000,000 Ar. It never compares the amount to `current.agreedAmountAr`. An amount above the agreed price gives status `paid` through `paymentStatusFor`, and the larger number is saved as the declared amount.
**Why it matters**: A typo (an extra zero) records money the client never owed, and it is written to the payment history. Prices are a business rule that must be checked on the server.
**Suggested fix**: Reject an amount above the agreed amount with a clear error code, and use the agreed amount as the upper limit instead of the fixed 10 million.

### 🟠 Suspending a driver does not take them offline, `packages/api/src/routers/admin/drivers.ts:450`
**Problem**: When the decision is `suspended` for a driver (or vehicle), the code voids open offers but leaves `isOnline` and `isAvailable` true. The account ban path in `accounts.ts` sets both to false.
**Why it matters**: A suspended driver can still show as online in the dashboard count and in dispatch, until some other code checks verification status. This depends on the dispatch feature, which is not built yet, so it is a risk, not a proven bug.
**Suggested fix**: Set both flags to false in the same transaction when the driver subject becomes `suspended`. Check the spec to see whether a vehicle suspension should do the same for the driver.

## Minor
### 🟡 Replay lookup is not tied to the booking or payment, `packages/api/src/domain/booking-status.ts:70` and `packages/api/src/routers/admin/bookings.ts:384`
The replay check finds an earlier event by actor and request id only. If the same request id is sent for a different booking, the call returns the first booking's result and changes nothing. The same applies to `resolvePayment`. Add the booking id (or payment id) to the lookup.

### 🟡 Dashboard counts mix simulated and real data, `packages/api/src/routers/admin/dashboard.ts:57`
`created`, `cancelled`, `noDriver` and the `created` series ignore the "include simulated" switch, while `completed`, `offers` and the live counts honor it. The figures will not add up when the switch is off.

### 🟡 One query per row on the team list, `packages/api/src/routers/admin/team.ts:46`
`suspensionIncomplete` runs one query for each of up to 25 rows. Fine now, but it can be one grouped query.

### 🟡 Search text has no length limit, `packages/api/src/routers/admin/accounts.ts:88` (and the `q` inputs in bookings and drivers)
`q` is an unbounded string used in an `ilike` with a leading wildcard. Add a `max` length.
